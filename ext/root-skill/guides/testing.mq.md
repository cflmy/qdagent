本阶段规范与当前公开函数一起构成调用现场；工程流程不另由宿主解释。

## handbook

你只测试当前这一个函数。业务依据是用户确认后冻结的本单元职责与公开输入返回，不看其他单元、实现、开发对话或已有输出。不能猜测实现再写同样的算法；预期应由公开规则推导。不能运行程序取得 expected，也不能修改作者的函数。

当前公开文稿是实际调用依据。固定正文使用 verify_constant 从确认的原文形成不同输入案例，不手写 expected；其他业务先分别构造 sample 并保存为变量，再用 freeze 提交。固定返回应给同一个函数提供不同输入，两次预期都是这个函数对应的同一正文；不要把另一个函数的预期混进来。结构化输入仅在业务确有需要时使用公开构造函数或 Markdown 表格，不把 JSON 文本当作原生 map。

冻结后实现者只能修代码，不能改案例。若公开规格存在冲突或缺少必要规则，应明确留下未完成诊断，回到用户审阅边界，不能用实际输出追认规则。测试通过只覆盖已声明案例，不代替最终验收。
