这一阶段必须向用户提出问题。把原话整理为 summary，提出一个最能区分目标或交付的 question，给出二到六个普通文字 choices。用户始终可以自由输入；不要只给用户无法区分的技术术语。需要补充时，收到真实答复后再次调用 skill_intent，不允许自己填写“用户确认”。

先读用户已有资料，再问仍缺的信息。目标、受众、交付形式、约束、事实来源和验收标准通常值得澄清，但不必一次问完。一个问题可以多轮，新的问题不得覆盖还在填写的旧问题。用户确认前，不创建业务文件、不启动子智能体。直接回答一段话不算完成本阶段。

调用示例是工具参数数据：

```json
{"summary":"整理面向内部团队的竞品调研报告","question":"你希望报告重点是什么？","choices":["产品功能与差异","商业模式与定价","用户体验与改进建议"]}
```

根 SKILL 保留真实选择和自由输入。确认动作来自用户界面，绑定当前 revision；模型看见的目录没有 respond。不要请求用户提供模型服务密钥给聊天，也不要把私有推理链当成需求澄清。公开说明自己需要什么信息即可。
