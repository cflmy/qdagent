# React / Go / Python 的渐进迁移

## 当前交付边界

HTTP、认证、SQLite 查询、SSE、文件上传与静态站点由 Go 承担；交互状态由 React 承担；顶层智能体循环由独立 Python 进程承担。Marqdo 继续承担标准库、插件和实际任务工具，官方 View 继续解释 Marqdo 文稿。

这次不修改 Marqdo 编译器。既有 SQLite 模式保留，添加 qd_runs、qd_run_events、qd_http_sessions、qd_http_logins、qd_model_health。既有工具、Office 和一层子任务通过 Marqdo 适配器使用；因此原实现仍是能力依赖，但不再嵌入网页进程。

## 已发现并修复的接口问题

- 旧前端把同一回调的空效果覆盖已有正文；新前端使用 React 状态与按任务隔离的请求，工具卡片有稳定 key。
- 原来整个会话、插件、模型清单一起恢复，慢调用阻塞全部入口；新接口独立查询 SQLite，各资源单独加载与报错。
- 原有模型请求使用 stream=false；新循环直接读取供应商原生增量，并保存可恢复事件。
- 工具目录的最小 schema 没有 array.items，供应商需要单独投影；该投影不修改执行权限。
- Ollama 的 arguments 要对象、工具回复使用 tool_name；OpenAI 使用 JSON 字符串与 tool_call_id，不能共用同一个请求对象。
- 预算用尽必须作为服务错误显示，不能归咎于界面、伪造回答或静默切换模型。
- favicon 补齐；LanguageDetector 属于浏览器提示。

## 后续迭代顺序

1. 把现有子任务循环迁入独立 Python supervisor，保留角色、工具子集、深度、预算、真实交接与完成证据；再引入有界并行与取消传播。
2. 把插件目录整理为版本化能力清单，用同一规范生成模型工具描述、前端说明和运行白名单，避免人工重复登记。
3. 对仍通过 Marqdo 调用的工具边界补契约回归，逐个评估把 Go/Python 适配抽象为可调用 Marqdo 插件；不要求 HTTP 宿主重新进入同一个 VM。
4. 对话和事件分页、任务归档、引用材料检索、模型额度状态和运行成本可视化。
5. 保持官方 View 的只读合同，进一步支持携带受限项目依赖的阅读包，让工程文稿也能完整预览。

迁回 Marqdo 的依据应是实际合同和故障隔离验证，不能仅以“全部文件都使用一种后缀”作为完成标准。用户看到的交付始终应是可操作、可恢复、能查到实际依据的工作台。


## 2026-11-13 部署验收

生产入口 `https://agent.qdqc.com` 与本机 `7964` 已切换到 `qdagent-react-go-0.4.0`，容器健康正常。切换前将 SQLite 在线备份保存在原数据卷 `pre-go-migration.sqlite3`。切换后的任务、消息、模型配置数量分别仍为 18、18、7，数据库完整性检查通过。

- React / TypeScript 生产构建通过。
- Go 的 10 项检查在 race 模式下通过，包括原生 SSE 首段、持久终态、取消整个工作进程组和账号隔离。
- Python 的 6 项检查通过，包括 Ollama 原生增量、消息转换、数组参数投影与工具失败不能标为完成。
- Playwright 直接使用真实 Go API 验收桌面、手机、模型、插件、上传、文稿、面板调宽与本机 Qwen 的实际写入、读取；文件内容和工具真实参数逐字核对。
- 隔离容器里的本机模型、Marqdo ABI 文件工具和官方只读 View 均通过实际调用，非静态样例。
- 两个登录入口均跳转到身份站，回调与入口一致，携带 PKCE S256 与 nonce。未代替用户完成身份站交互登录；切换后用户需要重新登录一次。

SSE 的完成消息带最终持久状态和回答，避免取消与末尾状态事件之间的竞态让界面一直运行。官方 View 的正文锚点使用 `aria-describedby` 对应注解，阅读器沿用该合同，原生 details 保持展开状态。

当前共享服务在真实请求中返回预算已用尽；默认本机模型可用。小模型的内容准确性不等于工具链正确性，仍应检查交付文件与实际工具收据，不把模型自称通过当作验收证据。
