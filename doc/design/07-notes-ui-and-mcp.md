## 0. 为什么要单独强调这两点

OpenClaw / Hermes 已经证明「长驻助手 + 多通道 + 工具」可行。求道智能体（qdagent）要和其他智能体 **一眼可分**，不能只比「谁工具更多」，而要押在：

1. **知识长什么样、怎么被看见** — 像笔记/知识库，而不是又一个聊天气泡墙。  
2. **知识怎么进别人的 AI** — 即使用户继续用 Cursor / VS Code / Claude 自带模型，也能通过 **MCP** 把求道沉淀的知识与写回能力接进去。

一句话：

> **求道首先是一份可执行、可浏览的求道笔记；聊天与模型只是写入笔记的笔。**  
> **MCP 让这支笔可以握在任何编辑器的 AI 手里。**

## 1. 笔记式展示界面（Notebook Surface）

### 1.1 体验对标（不是聊天对标）

| 参考形态 | 借鉴什么 | 不照搬什么 |
|----------|----------|------------|
| Obsidian / Logseq | 双向链接、图谱感、本地文件为王 | 不必做成另一套 PKM 宗教 |
| Notion / 飞书文档 | 块级排版、侧栏目录、舒服阅读 | 不必上重型协同编辑首期 |
| Apple Notes / 备忘录 | 列表 + 正文两栏、轻量 | 功能过简 |
| Marqdo `view` | 可执行文档、结构/执行/变量 | 需产品化成「助手首页」 |

**反模式：** 把主界面做成「ChatGPT 克隆 + 高级设置」。聊天可以有，但 **默认着陆页应是笔记/知识浏览**。

### 1.2 信息架构（修订）

```text
┌────────────┬──────────────────────────────────────────────┐
│ 侧栏       │  主区（笔记画布）                              │
│            │                                              │
│ 求道库     │  标题 / 标签 / 时间                           │
│  · 今日    │  ─────────────────────────────────           │
│  · Runs    │  Markdown 正文（.mq.md 渲染）                 │
│  · Skills  │  · 叙述段落（注释）                           │
│  · KB      │  · 可执行块高亮（*…* / ##）                   │
│  · 会话    │  · 写回卡片嵌在对应语句下（像批注）           │
│            │                                              │
│ 快捷       │  底栏或右侧：Ask / 续写 / 晋升为 Skill        │
│  · 新笔记  │                                              │
│  · 录音    │  可选：分屏「对话」贴在右侧抽屉，不占默认主视角 │
└────────────┴──────────────────────────────────────────────┘
```

| 区域 | 行为 |
|------|------|
| **Runs 笔记** | 每次执行对应一篇笔记；可按日/标签浏览 |
| **内联批注** | 工具调用与结果显示为笔记中的 callout，而非独立 JSON 面板 |
| **大纲** | 标题树 + 函数大纲（对齐 Marqdo Structure） |
| **链接** | `[[run_id]]` / `[[skill:name]]` 双向跳转 |
| **对话抽屉** | 需要时打开；发送后 **主区跳到新生成的笔记** |

### 1.3 视觉与交互原则（差异化）

1. **纸感优先**：充足留白、清晰字体层级、弱边框；避免仪表盘式卡片墙。  
2. **一篇笔记 = 一次求道**：标题可用用户问题摘要；副标题显示模型/耗时/`run_id`。  
3. **可执行可见**：语法块有克制的高亮，不伪装成纯散文。  
4. **一键再运行**：笔记顶部 `Run again` → `marqdo run` 同文件或派生子 run。  
5. **晋升动作显眼**：「收藏为技能 / 写入知识库」放在阅读路径上，而不是埋进设置。

### 1.4 与聊天模式的关系

| 模式 | 何时用 |
|------|--------|
| **笔记模式（默认）** | 回顾、审计、学习、整理知识 |
| **对话模式（抽屉/次级）** | 快速追问；结束后仍落成笔记 |
| **语音** | 入口在笔记页麦克风；转写写入新笔记正文 |

## 2. MCP：把求道接进「别人的 AI」

### 2.1 战略意义

| 接入方式 | 用户还用谁的模型 | 求道扮演 |
|----------|------------------|----------|
| OpenAI 兼容 `/v1` | 求道 Gateway 编排（可换底层模） | **大脑 + 笔记本** |
| **MCP Server** | Cursor / VS Code Copilot / Claude Desktop / Windsurf 等自带 Agent | **笔记本 + 工具箱**（模型在编辑器侧） |

第二种场景极其重要：许多用户不愿换编辑器里的默认模型，但仍希望：

- 检索求道知识库  
- 把结论/步骤 **写回** `.mq.md`  
- 列出/打开某次 Run  
- 晋升 Skill  

→ **不抢模型，只抢「沉淀与召回」**，可用性大幅上升。

### 2.2 MCP 能力规划

#### Tools（动作 — 会改变世界 / 写盘）

| Tool | 作用 | 沉淀 |
|------|------|------|
| `qd_search` | 检索 runs/kb/skills | 只读 |
| `qd_get_run` | 按 id 取笔记全文/摘要 | 只读 |
| `qd_append_note` | 向指定笔记或新笔记追加段落 | **写 `.mq.md`** |
| `qd_capture` | 捕获「当前结论」为一次 Run 骨架 | **强制建 run** |
| `qd_promote_skill` | 从 run 晋升 skill | 写 skills/ |
| `qd_list_recent` | 最近 runs | 只读 |
| `qd_run_skill` | 执行某 skill（可选，权限更高） | 执行 + 写回 |

#### Resources（只读上下文）

| Resource URI 示例 | 内容 |
|-------------------|------|
| `qdagent://kb/...` | 知识条目 |
| `qdagent://runs/{id}` | 某次执行笔记 |
| `qdagent://skills/{name}` | 技能文档 |
| `qdagent://today` | 今日索引 |

#### Prompts（可选）

- `/qd-capture`：引导模型把本轮结论结构化写入求道  
- `/qd-recall`：先搜索再回答  

### 2.3 「不用我们的 AI 也能沉淀」流水线

```text
编辑器 Agent（Cursor 等自带模型）
        │
        │  MCP tools/call: qd_capture / qd_append_note
        ▼
 qdagent MCP Server
        │
        ▼
 runs/*.mq.md  /  kb/  /  skills/
        │
        ▼
 笔记界面 / marqdo catalog / git
```

关键约束：

1. **写盘工具默认需用户批准**（编辑器侧 MCP 审批）；服务器侧再做路径 jail。  
2. `qd_capture` 生成的 Run 带 `surface: mcp`、`editor: cursor|vscode|…`。  
3. 即使没有走 `ext/ai/agent` 推理，**笔记仍符合同一 Schema**（与审计文档一致）。

### 2.4 客户端覆盖

| 客户端 | 配置位置 | 传输 |
|--------|----------|------|
| Cursor | `.cursor/mcp.json` / `~/.cursor/mcp.json` | stdio 或 SSE |
| VS Code + Copilot | settings `mcp` / servers | stdio / SSE |
| Claude Desktop | `claude_desktop_config.json` | stdio |
| 其他 MCP 客户端 | 同协议 | 同左 |

示例（stdio）：

```json
{
  "mcpServers": {
    "qdagent": {
      "command": "qdagent-mcp",
      "args": ["serve"],
      "env": {
        "QDAGENT_ROOT": "/home/user/work/qdagent-data"
      }
    }
  }
}
```

### 2.5 与 OpenAI 兼容 API 的分工（双轨）

| | OpenAI `/v1` | MCP |
|---|--------------|-----|
| 模型在哪 | 多在求道侧（或透传） | **在编辑器侧** |
| 典型用户 | 想把编辑器「模型地址」指到求道 | 想继续用编辑器默认 Agent |
| 沉淀 | 每次 completion 自动 Run | 靠 tools 显式/半自动 capture |
| 优先级 | MVP 核心之一 | **同等产品级差异化，紧随或并行调研** |

**产品话术：**  
「可以用求道当模型，也可以只用求道当记忆。」

## 3. 和其他智能体的「可感知差异」清单

| 维度 | 常见 Agent | 求道 qdagent |
|------|------------|--------------|
| 打开产品第一眼 | 对话框 | **笔记库** |
| 历史 | 气泡列表 | **一篇篇可执行笔记** |
| 接 Cursor | 换 base_url 或没有 | **base_url 或 MCP 二选一/同时** |
| 知识 | 向量黑盒 | **文件 + 大纲 + 批注 + git** |
| 再执行 | 难 | 笔记上 Run again |
| 品牌名 | 助手/龙虾/赫尔墨斯 | **求道** — 求索过程本身被记录 |
