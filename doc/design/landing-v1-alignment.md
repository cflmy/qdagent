# 求道公共首页 · 第一版

首页是由 Marqdo 可执行文档驱动的智能体产品介绍。工作台单独位于 `/app`，公共首页不等待身份、模型与插件接口。

设计稿由内置 imagegen 生成，提示词保存于 [landing-v1-prompt.txt](landing-v1-prompt.txt)，原稿为 [landing-v1.png](landing-v1.png)。实际返回尺寸为 **1003 × 1568**，以这个实际尺寸建立对齐基准，不以提示词请求尺寸代替成品尺寸。

## 素材与文案

- QD 使用 SVG 折面几何，沿用 Marqdo 原始标识的深橄榄绿、金色和切面语言，见 `frontend/public/brand/qd-mark.svg`。
- 使用本地 Noto CJK 字体的 WOFF2 子集，不依赖第三方字体 CDN。字体制作脚本与许可随工程保留。
- 样稿明确标为“文稿示意”，流程与交付卡片是产品讲解，不假称当前正在执行任务。
- 主张文档驱动、知识编译、统一工具调用、可验证收据、官方 View 阅读和知识复用，不使用虚构客户、指标或模型能力保证。

## 登录问题与验证边界

用户提供的“身份站暂时不可用”只会在身份站发现阶段返回。生产容器的 Python 与独立 Go 冷启动探测目前均成功，旧实现没有保存足够诊断，不能据此断言当时是 DNS、TLS 或身份站错误。

本轮增加有界 GET 重试、超时、安全阶段日志与可重新登录的首页错误提示；保持 TLS、签名、issuer、audience、nonce、state、PKCE 和主体一致性校验。授权码兑换不自动重试，回调成功进入 `/app`。

完整协议回归使用隔离模拟身份站、真实 RSA 签名、真实 HTTP 令牌与 userinfo 端点，覆盖发现 503 后恢复、PKCE、浏览器 cookie、成功建立会话、nonce 错误、主体不一致、旧 state 重放、令牌交换不重试以及失败页面不泄漏供应商原始响应。真实身份站的账号交互登录仍需实际账号完成，模拟测试不冒充该验证。


## 远程验收

`qdagent-react-go-0.4.1` 已部署到原有 7964 服务。直接访问 `https://agent.qdqc.com` 的真实 Chromium 验收，没有页面 JavaScript 异常；文稿、流程条、卡片组、开始使用区与页脚坐标与上述本机测量一致。远程截图见 [landing-v1-production.png](landing-v1-production.png)。

本机与远程登录入口均成功返回身份站授权跳转，回调分别为 `http://127.0.0.1:7964/oidc/callback` 与 `https://agent.qdqc.com/oidc/callback`，包含 S256 和 nonce。用户报告的原始发现故障目前未复现，不将网络恢复等同于已证实原始根因。

12 项 Go 检查（race 模式）与 8 项浏览器检查通过。浏览器测试可通过 `QDAGENT_START_TEST_SERVER=1` 自行启动和清理专用 17964 loopback 服务，避免长期终端会话结束影响验收。


真实浏览器进一步从求道点击登录，已到达 `id.cflmy.cn/oauth2/authorize` 的“授权登录”页面，正确显示“CFLMY企业应用qdagent请求授权登录”，未出现客户端或回调地址拒绝。此验证止于账号输入前，不记录或请求用户密码。

生产 SQLite 的任务、消息、模型配置仍分别为 18、18、7，完整性检查通过；服务仍只通过 7964 对外提供。


用户随后实际使用统一身份认证登录，并明确确认“已成功进入工作台”。至此，真实账号授权与回调也得到人工验收；这与自动化模拟身份站测试、无账号浏览器跳转检查分别记录。
