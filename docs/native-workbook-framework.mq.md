本文记录本轮真实用户任务暴露的问题，并约束接下来的实现。它补充 document-driven-agent.mq.md，保留用户确认、角色隔离、来源权限与不可伪造的执行证据。

## audit

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 已核实的问题与原因 |

用户任务中的 report 实际提交的是 Marqdo 函数调用，并非供应商 tool_calls 动作 JSON。然而文章被放进带转义的长字符串，再经过 literal 模板序列化为 json.parse 表达式。运行诊断又被塞进 Result.message，前端直接 JSON.stringify 整个嵌套记录，所以源码、反馈和展示都缺少可阅读的文稿结构。

更严重的问题是实际能力不匹配。research 职责要求查阅 NASA、ESA 等互联网来源，但当前调用现场没有浏览器；报告没有真实来源获取记录，不能把模型写出的引用当成已经核实。将不确定的研究和写作结果作为固定 input/expected 字符串比较，也不能验证研究真实性或文章质量。之前固定文本测试证明的只是固定返回流程，并未证明研究写作任务可用。

不能仅修改构建标识或把 Python 入口换一个名字来宣布原生化。应使用 Marqdo 的实际工作簿、文稿绑定、知识编译、写时复制试运行与子任务；浏览器是提供真实观察的 ABI 插件，服务与模型通信中的 JSON 只是私有传输，不能成为模型必须手写的业务动作格式。

Return *"问题同时存在于任务表示、能力、验收和展示，不能只隐藏 JSON。"*.

## design

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 本轮实现边界 |

Go 直接启动 marqdo call 根文稿并转发事件，不经过 Python 智能体启动器。Python 若继续用于模型网络协议，只承担通信，不定义角色、提示、工具分派或阶段。现有 React、统一身份、SQLite 和 7964 服务入口保留，不修改相邻 Marqdo 核心源码。

长正文使用 Marqdo 原生绑定文稿单元，内容直接写在 Markdown 围栏中，避免模型为整篇文章逐字转义。生成的函数也应保留原文单元与叙述，不能把正文重新藏进大段 JSON。业务计算继续使用可读函数体，语法由官方解析器判断。试运行复用 ext/ai/sandbox 的真实写时复制机制，读取差异、验证结果后再发表；一份沙盒配置对象不能替代实际隔离执行。

浏览器使用单独受限容器，没有宿主工作区、Docker socket、身份 Cookie 或模型密钥。原生 Marqdo 插件提供打开页面、读取正文、来源与截图的能力；只允许公开网络的只读请求，重定向和子资源同样检查，阻止内网、元数据地址与直接旁路。任务之间不共享浏览器会话。浏览器未就绪或网站拒绝访问时明确失败，不能伪造搜索或资料。

研究与写作文稿使用对应的验收契约。研究必须有实际获取的来源记录；文章必须有实际文稿和可核对的引用。必要的来源依赖要先完成再交给写作者，不能把依赖关系当作无条件并行。独立测试者只根据公开意图制定规则，执行器检查实际产物；检查结构和引用存在不等于科学事实已经完全正确，最终业务判断仍需用户审阅。

Return *"文稿组织任务和实现，沙盒产生真实观察，验收按任务性质选择。"*.

## display

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 用户可见的执行过程 |

执行过程首先显示本次真实调用的 Marqdo 源码、可读结果、具体诊断位置和产物入口。错误中的嵌套 JSON 在边界解析成结构化诊断，不能把多层转义字符直接贴给用户。原始事件只放在显式调试详情中，正常阅读不依赖理解 JSON 字段。

浏览器展示实际页面截图、标题、来源地址和获取状态，提供可以跳转的链接。文稿仍由官方只读 View 阅读；来源、时间、摘要和检查证据与实际文件绑定。没有浏览或没有通过验收的任务保持未完成，不能通过改写进度文字假装能力已经存在。

Return *"用户看到真实文稿、网页与诊断，原始协议留在调试层。"*.

## implementation

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 本轮实际代码边界 |

生产入口由 Go 的 native_entry.go 直接启动根文稿。安装元数据统一保存在 ext/plugins.mq.md，Go 页面和 Marqdo 权限文稿均用官方 document.read_table 读取；页面按文件版本缓存，新增登记不再需要修改第二份 Go 清单。这是安装事实，不是模型动作或业务工具注册表。根状态、角色循环、依赖波次、独立验证与最终交付都在 root-skill 的普通函数中；旧 worker/agent.py 已删除。provider.py 只原样传输文稿组成的消息与供应商增量，不含角色、提示词、工具 Schema 或阶段路由。api 是当前角色文稿的普通 import 绑定，不是 JSON 工具名称路由；当前文稿中的公开函数就是唯一可调用接口。

规划新增 research_unit 和 document_unit。前者执行真实资料研究，后者依据材料撰文。依赖只指向已批准的前置职责，父程序按最多八个波次启动已经满足依赖的作业；无关职责仍按用户并发数同时执行，同一次根调用不会无限重试失败单元。前置研究没有有效证据时，写作保持等待。实现单元缺少冻结契约要求的实际来源时，每轮只开放 browse 函数；资料足够后才开放正文发表，不能只依靠模型服从“先研究”的提示。

实现者只接收当前公开规格、自己的真实观察与已就绪依赖的正文及来源，不收到依赖实现、独立案例或开发对话。测试者仍只接收无执行语义的冻结意图，研究文章使用事先冻结的正文下限和实际引用要求，不预测一篇尚未创作的逐字答案。普通程序继续使用独立输入预期，不能由作者把精确契约降为文档检查。

作者把原文写在绑定的 Markdown 围栏中，系统保存 solution/documents 下的实际正文，并生成解释来源、读取原文和检查摘要的 Marqdo 函数。文章是数据文档，函数是可执行交付；两者都可阅读。最终确认再次核对每份源码和正文摘要，改动其中任何一份都不能沿用旧批准。结构和引用检查不等同于语义质量判断，最终仍需用户审阅。

Return *"流程和能力由普通文稿定义，真实观察与版本证据决定能否继续。"*.

## compatibility

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 未修改核心时的兼容处理 |

本轮发现官方调用解析器对三反引号围栏的处理不能直接保留长围栏内的嵌套围栏。求道 ABI 因而复用官方 host_document_code_blocks 取得原文、语言与字节范围，再把数据单元交给官方 AST 验证绑定。受限调用的导入、函数、表达式和角色权限仍由同一个官方解析器校验，没有另写正则语言解析器。执行器内部只适配原生参数的传值形式；用户与事件记录保留原始围栏文稿，正文不要求模型二次编码。

官方 CoW 的内存执行器仅解析内嵌标准库导入。可信试运行文稿因此将已经校验的单元源码与固定 main 调用组合后执行，既没有修改核心，也没有退回普通目录执行。每个案例单独 open、run、diff、discard，底层必须为空，只向上层交接摘要仍一致的获准正文。候选写入不会进入真实任务文件；网络、进程与插件效果关闭。

这些适配都有真实调用与隔离负例，不能依据一份宣称启用 sandbox 的配置对象判断执行安全。将来升级底层 Marqdo 后，应先重跑嵌套围栏、真实返回和 CoW 文件隔离用例，再考虑删除已不必要的兼容层。

Return *"兼容逻辑留在求道插件，源码语义与验证仍复用官方能力。"*.

## browser

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 隔离浏览插件的实际能力与限制 |

browser 插件通过普通 open 函数接入已登记扩展。服务是独立非 root Chromium 容器，启用浏览器用户命名空间沙盒，去除宿主 capabilities，根文件系统只读，只给有界临时目录和共享内存。浏览服务不发布端口，仅凭私有服务凭据接受求道请求；没有 Docker socket、工作区挂载、OIDC Cookie 或模型密钥。

只读页面访问逐跳检查 DNS 所有地址并固定连接到已检查地址，阻止私网、特殊地址与元数据入口。Chromium 重定向不可靠地经过同一个拦截器，因此重定向由受限传输逐跳读取、检查后才导航最终地址；子资源使用相同边界。浏览器直连代理关闭，站点脚本、写请求、下载、WebSocket 和服务工作者关闭，每次使用全新会话。公开网站也可能拒绝访问或要求脚本交互，这些情况保留真实失败，不假装完成登录或交互操作。

正文快照、原始 PNG、来源地址、时间和摘要由 Marqdo 标准文件与字节函数保存。下一轮模型只接收有界摘录，完整证据可由用户在工作台打开。仅在隔离验收容器中启用固定回环资料站，生产 Compose 没有该测试配置。Chromium 的 seccomp 文件来自 Playwright 官方配置，增加 chroot 系统调用允许项以配合已关闭的宿主 capabilities；没有启用 SYS_ADMIN 或关闭 Chromium sandbox。

Return *"浏览取得可核对的观察，不能把网页或模型记忆当作已核实事实。"*.

## verification

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 测试与使用边界 |

确定性验收覆盖原生正文里的引号、换行、Markdown 与嵌套围栏，真实调用后的返回逐字比对；CoW 写入有真实差异，宿主没有同名文件。研究来源来自实际 Chromium，快照与 PNG 均保存；下游写作在研究就绪前不会启动，未访问的网址不能通过引用契约。修改正文后旧证据失效，测试角色无法调用浏览器，也看不到研究笔记或实现。

前端浏览器验收检查实际调用原文、解码后的定位诊断、默认关闭的协议调试项、来源链接和 PNG 预览。认证与任务所有权仍由 Go 检查，内联显示只接受实际 PNG、JPEG、WebP；SVG 等主动内容不进入图片预览。旧文件下载和官方只读 View 保留。

实际模型仍可能使用错误语法或误解需求。有限修复指引只写在 Marqdo 文稿中，不接受 Python 三引号、未知参数、猜测来源或作者改写测试来制造完成。共享 smart/default 真实完成了实际浏览、研究笔记、依赖写作、独立引用验证与整合，到达用户审阅阶段；该验收的框架由开发操作者明确确认，没有代替真实用户批准。4B 本机模型曾误用三引号并在有限预算内失败，这些失败被保留，不据此声称任意小模型都可靠。模型连接正常不代表任务完成；独立规则、实际试运行和用户确认分别记录。历史任务的已批准范围不会自动迁移，必要时由用户明确返回框架阶段重新审阅。

Return *"以实际输出、隔离负例和真实用户可见行为核验，不用漂亮状态代替证据。"*.
