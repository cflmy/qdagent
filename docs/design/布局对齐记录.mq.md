# 设计与实际页面

| 位置 | 设计基准 | 实际组织 |
|---|---|---|
| 首页侧栏 | 267 px | 品牌、工作区、任务列表、底部四个导航 |
| 页首 | 46 px | 工作区名称与产物开关 |
| 右侧文稿区 | 496 px | 标签、文件标题、官方 View、下载 |
| 模型选择 | 820 × 734 px | 居中标题、共享模型、本机模型、个人模型、确认底栏 |

以上尺寸用于默认桌面视口。用户拖动后的宽度继续尊重已保存的偏好，双击分隔条恢复基准。手机收起侧栏，将模型正文限制在独立滚动区，确认和取消保留在底部。真实会话内容决定正文高度，设计图中的示例任务不作为用户记录生成。

[首页实际布局](assets/workbench-implemented.png) 与 [模型选择实际布局](assets/model-picker-implemented.png) 来自当前原生组件和官方 WASM 的 Chromium 截图。首页使用明确标注的确定性验收对话与真实 View 文稿；模型目录使用专用验收账号可见的共享配置。这些图片验证组件位置和可见状态，不冒充真实模型推理、用户 OIDC 登录或生产对话。

# 目录加载与失败

| 状态 | 用户看到的内容 | 来源 |
|---|---|---|
| 等待目录 | 读取提示，隐藏个人模型空态 | 独立 GET /api/model_catalog |
| 成功 | 共享、本机、个人配置及真实选择 | 当前账号公开目录 |
| 失败 | 明确的读取失败提示 | 原始请求的失败结果 |
| 重新打开 | 再次发起目录读取 | 正式 open_model 入口 |

模型目录不再依赖会话恢复、插件扫描或档案锁。服务端仍通过认证网关注入账号，不返回凭据。目录展示只代表已配置，不声称模型服务已在线。默认项仅在用户尚未选择时采用；打开和取消不改变下一轮已经确认的模型，更不修改运行中的任务。

前端类效果通过选择器合并，桥接有固定应用顺序。需要保留的 is-open 必须出现在同一选择器的最终添加列表中；错误分支不能同时添加和删除 is-catalog-error。目录高亮通过一次性回调安排在 HTML 建立之后，这些规则属于可读 Marqdo 客户端，不引入第二份业务 JavaScript。

# 验收边界

桌面 1586 和手机 420 的 tests/harness-ui.mq.md 场景均检查了官方 WASM 的状态、展开卡片和原生文稿。模型视觉验收通过 .marqdo/model-reference-client.mq.md 只替换网络响应边界，实际打开、解析、默认选择及高亮仍运行产品入口，分别观察成功、失败和手机场景。所有变更继续接受 narrative-ratio 检查，再通过 deploy/manage.mq.md 构建并启动 7964 容器。
