# 从目标到结果

先生成 [工作台设计图](assets/agent-workbench-v2.png)，并保存 [完整生图提示](assets/agent-workbench-v2-prompt.txt)。采用象牙白、橄榄绿和细边框，延续 Marqdo 的阅读气质。设计图用于判断入口层级与空间，不是运行证据；工程截图来自真实客户端、官方 WASM 和原生组件。

左侧保持任务列表，新任务和历史切换不再藏在输入栏浮层。文件、知识库、插件与模型配置位于导航底部。页面首部显示工作区名字。中心是完整对话，执行步骤以较小字号进入对话阅读顺序，详情展开后不会因普通轮询重建而折叠。输入区提供多行编辑、附件、紧凑模型选择、发送和停止。

右侧检查区阅读真实文件与执行摘要。产物按钮打开已登记文件；工作目录文件由所有权校验后的接口列出。Markdown 使用已有安全渲染器，Marqdo 文档使用官方 View 的 sanitized_html。当前版本将单文件放进隔离阅读项目，允许已安装 lib、ext 导入；自定义项目相对导入暂时显示明确诊断和转义源码，后续需要携带完整依赖的只读阅读包。阅读不会执行文档或改变插件权限。

# 状态与工程边界

会话身份、视图序号和文件请求序号分别负责所有权与异步排序。旧文档响应和旧失败都不能覆盖新选择。模型标题来自账号已有配置，首次优先选择实际可用的 smart/default；手动选择以后不被任务切换重置。密钥不进入前端或设计材料。

所有产品决策与文件操作仍是 Marqdo 源码。键盘桥接唯一新增能力是传递修饰键与输入法元数据，作为本地 Web 插件 ABI 适配注册。Shift+Enter 保留换行，输入法确认不触发发送。不修改 Marqdo 源码，不新增业务 JavaScript。

# 可复现验收

从工程根通过 marqdo call 调用 tests/harness-ui.mq.md 的 run，chrome 提供现有 Chromium 路径。mode 可取 preview、activity、closed，width 可取 1600 或 420。测试只替换网络和调度边界，真实客户端负责状态与显示，原生 View 片段由生产读取函数生成。通过标记、实际 DOM、请求身份和展开卡片必须同时成立。

tests/input-ui.mq.md 覆盖分块上传、确认游标、自定义模型保存与选中高亮。tests/task-ui.mq.md 覆盖两个会话、Enter、直接回调状态与轮询后展开。tests/workbench-ui.mq.md 覆盖真实产物入口。确定性浏览器夹具不冒充真实模型、OIDC 登录或公网部署，实际部署另外核对 build-info 的修订与源码摘要。
