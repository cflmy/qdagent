办公能力继续遵守文稿就是 SKILL、普通函数就是工具。根流程按当前现场加载有限手册，不向模型发另一套工具 JSON Schema，不把提示词写入宿主代码。本轮不修改 Marqdo 核心，受限 OOXML 读取作为求道 ABI 插件能力接入。

## workflow

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 意图、函数段、实际文件和用户验收的联系 |

意图拆解时记录真实办公格式：task 的 artifact_kind 为 docx 或 pptx；正文方法仍是 document、research 或用户明确提供原文时的 text。基本方案沿用这个确认，不能因为模型没有重复填写就丢掉格式；冲突明确拒绝。实际 Word/PPT 手册位置写进方案。当前一份框架只交付一种主办公格式，多格式需要与用户约定分批任务，不能悄悄只完成一种。

主方案以 ## 函数段划分内容职责，各作者并行完成自己的段落并经过独立验证。测试者只看冻结的公开意图，不直接读取作者文件或上传原件。上传材料中的有效要求应先写入框架，交用户确认后再用于测试。模型仍通过普通调用表达操作，本轮公开交付文稿中的 assemble 函数会组装已验证正文，实际执行必须在授权现场。

组装沿用方案顺序，Word 保存章节段落，PPT 确定性拆成有界文字页。模型无需重传整篇文章，也不能在结束时另写一份未经独立验证的内容。没有实际办公文件时 finish 会失败；文件、源稿、快照或单元证据变化都会使旧交付失效。相同且仍有效的产物可以复用，断线继续不会无故重新生成。最后进入用户审阅，生成成功不等于用户已经验收。

Return *"确认格式 → 按函数段并行创作与验证 → assemble → finish → 用户审阅。"*.

## reading_and_revision

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 读取、局部编辑和版本保存的实际保证 |

read_office 的路径来自当前任务上传文件或已登记产物。每次最多八千字符，next_offset 不为空表示尚未读完；继续读取必须使用该偏移，不能把摘录称作全文。输入上限五十 MiB，ZIP 声明展开总量最多十六 MiB，部件数量、XML 大小、嵌套深度与文本量均受限制。只读解析不解包到磁盘、不执行宏、不跟随远程关系、不加载 Office。DTD、越界、符号链接逃逸及损坏格式明确失败。

局部编辑适用于本插件生成且有结构快照的版本。先 inspect 核对顺序，然后按从零开始的位置替换、插入或删除章节；PPT 的自动封面不计入内容页位置。原二进制、Markdown 与结构快照的实际摘要都要匹配，新版本使用新身份，原版本保持不变。删除最后一节、未知位置、超长内容和修改过的旧证据都不能产生成功版本。

外来文档可提取文字后重新创作，但目前不能无损保留复杂表格、图片、图表、备注、修订痕迹和原版式。基本生成器按文字处理 Markdown，最多二十章或二十张内容页；过长应在规划中精炼或分批，不能静默裁剪。PDF 通过容器预装 LibreOffice 实际排版，只接受本次固定模板新生成的包，不把任意上传包交给排版进程。源稿继续可读，复杂对象未处理必须向用户说明。

Return *"只读提取保持原件，局部修订保留旧版，未知复杂对象与版式限制明确披露。"*.

## experience

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 文件树、执行经过与预览的展示要求 |

执行区域显示实际读取的文件名、偏移、总量、是否读完，以及取得的文字。实际办公交付显示可读题目、格式、大小、原件预览、Markdown 源稿与附带 PDF。没有 PDF 时如实说明，不用一个下载按钮冒充已经排版。实际调用文稿、诊断和原始协议仍可核对。

工作区文件树展示真实交付和源稿，保留底层 ZIP 部件、重新解包与 LibreOffice 配置供审计，但不让它们淹没用户文件。过滤只针对实际办公登记对应的产物目录，其他用户工程的 package 文件夹不受影响。显示名称从可读题目派生，存储路径与身份保持稳定；UUID 目录在展示时使用资料目录名称，不要求用户阅读长标识。

原件仍通过现有隔离文件阅读器预览，Marqdo 文稿保持官方只读 View。文件查看不赋予代码执行权，不向阅读器暴露认证接口；所有下载与读取继续核对当前任务所有权。新增格式或复杂对象时必须同时维护文件生成、快照、摘要、预览与回归，不能只改前端展示或提示词。

Return *"让用户看见实际内容与文件，技术部件留作审计，显示名称不替代存储身份。"*.
