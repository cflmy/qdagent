本文记录 2026-11-14 的架构审查和修复依据。适用于求道的根流程、子智能体、模型接入、测试与前端。普通 .mq.md 本身就是 SKILL；其中可调用函数就是工具。多文件通过 index.mq.md 组织，单文件不强制套一层入口。不得另外建立一套 SKILL 注册器、业务工具别名表或模型动作 JSON 语言。

## architecture

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 本次开发必须遵守的架构约束 |

上一版存在真实偏移：worker/agent.py 与 worker/root_skill.py 保存角色提示、阶段说明、修复指令、工具 Schema、名称映射、阶段调度和自动兜底；执行仍依赖模型 tool_calls JSON 经中央分派后再调用 Marqdo。实现智能体还能编写自己的验收案例。扩大上下文只能暂缓这些结构问题，不能实现文稿驱动。

修复后的入口必须直接执行根 Marqdo 文稿。根函数读取真实状态，决定当前阶段、暂停、恢复、子任务和结束条件。模型只看当前调用现场所需的目标、文稿、公开契约和材料，返回普通 Marqdo 调用文稿；官方解析器检查后通过 marqdo call 执行其函数。参数、函数绑定和返回属于 Marqdo，不由宿主解释一套模型动作协议。

所有发给模型的固定指令，包括角色、任务框架、修复建议、重试和结束约束，只能定义在 .mq.md。宿主允许模型网络传输、ABI、SQLite、文件隔离、进程和事件转发，不得拼接隐藏指令、决定业务阶段或产生兜底方案。每个模型请求保留指令源位置与源码摘要，用户输入和运行诊断则单独标记来源。HTTP 和 ABI 的必要 JSON 编解码属于传输，不得成为第二份业务定义。

Go 保留身份与会话、API、SSE 和前端服务。Python 仅允许保留不含提示词和业务状态的网络传输或进程转发；替换语言本身不能解决控制权问题。系统操作通过本仓库 ABI 插件补齐，不修改 Marqdo 核心源码。插件安装登记与效果权限仍需保留，安装一份动态库不等于授予其所有内部函数。

Return *"文稿定义流程与提示；Marqdo 绑定并执行函数；宿主只提供受限 I/O。"*.

## workflow

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 必经阶段与真实确认边界 |

意图拆解必须向用户提出问题，支持选择、自由输入和多轮澄清。用户确认后才能生成基本方案。基本方案以函数边界、输入、返回和验收要求形成实际文稿，右侧使用官方 View 阅读；确认绑定确切源码摘要，不能用聊天摘要代替审阅。

框架确认后冻结公开规格。实现者与测试者使用不同上下文和受限工作根；可以按用户配置并行。实现者编写自己的函数，测试者从冻结规格生成独立案例。确定性执行器同时读取两份产物并调用实际函数，失败回到实现修复，不能让实现者改预期值来取得通过。用户要求变更规格时回到方案确认，旧批准不能沿用。

最后整合源码、叙述、真实用户交流与实际证据，再交用户验收。每个函数叙述应超过 50%，参数与返回表紧邻标题；操作尽量用有明确意图的 []() 写在正文中。未接通项在可见文字中披露，接受有限范围仍记录部分完成。编译、局部自检、独立测试、整合冒烟与业务验收必须分别记录。

Return *"意图确认 → 框架确认 → 受限实现与独立测试 → 整合验证 → 用户验收。"*.

## isolation

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 调用现场与独立测试的隔离标准 |

意图智能体只看用户目标和必要回答；规划者看已确认意图与相关能力；实现者看自己的骨架、规范、必要依赖接口与获准材料；测试者只看冻结的业务意图、公开参数返回和验收要求。上下文不附带全局聊天、整份实现、完整工具目录或其他子任务的内部过程。

测试投影从确认过的规格产生，不从实现者的解释生成。去除可执行标记、表达式、赋值、内部调用和控制流，保留业务含义和公开契约；使用官方解析结果校验投影没有可执行语句，不能用简单字符串删除冒充语义转换。公开业务规则仍应明确，例如负数是否允许，不得把必要验收规则一起删掉。

模型不能通过读取文件、改变路径、输出导入或调用 ABI 重新拿到被隔离的内容。测试者的执行根中没有实现，模型请求中没有实现，工具返回也不得泄漏实现。测试者不能读取开发对话、调用实现或使用实现者自报的 expected。独立测试先固定版本，再由确定性执行器运行；读取结果是观测，不能把结果复制成新的预期值来追认成功。

复用已有知识编译、稳定符号、提示文稿、上下文预算和子任务能力。索引只是可重建投影，函数和文稿仍是事实源。无法复用的解析能力通过 ABI 引用官方解析器，禁止维护另一份 Marqdo 正则解析器。调用会话按任务和角色隔离；结果交接必须明确，不共用默认会话。

Return *"角色只取得当前工作需要的文稿、值和权限；独立测试无法接触实现。"*.

## acceptance

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 必须用真实执行证明的验收项 |

修复必须证明：生产入口执行根 .mq.md；Python 不再包含模型指令、工具注册和阶段路由；模型供应商请求不带业务 tool schemas；普通 Marqdo 调用能到达现有能力。模型输出的调用必须由官方解析器绑定，未经授权的导入、宿主函数、环境读取和文件操作会被拒绝，不能把任意模型文本交给 Shell。

还必须证明：用户确认不能伪造；旧版本与源码变更失效；子任务有受限上下文、独立目录、真实并发与取消；测试者看不到实现，恶意植入的错误能由独立测试发现，修复后用同一测试通过。模型缺少有效调用或测试失败时保留未完成，不自动写一个猜测方案或生成漂亮的完成消息。

前端继续使用官方只读 View，显示实际函数调用、阶段、模型、源码定位与执行结果。同名文稿更新后展示新版本；未更新时不反复刷新。SQLite、统一身份、7964 端口与既有用户数据保持可用。迁移结束更新 README 与实际验证记录，明确哪些检查通过，不能把模型接口可连接当作任务已完成。

Return *"以真实 CLI、隔离负例、独立测试和浏览器链路验证；不得只检查提示词或模拟模型返回。"*.

## implementation

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 已落地的源码边界与新增能力方式 |

实现对应下表。新增能力时修改所属普通函数文稿及其验证，不恢复旧名称路由。运行时的 ABI 操作名只描述系统 I/O，不包含意图、框架、实现或验收等业务迁移逻辑。

| 源码 | 责任 |
|---|---|
| ext/root-skill/index.mq.md → runtime/index.mq.md | 固定真实入口、恢复、阶段、并行与等待用户 |
| state.mq.md、planning.mq.md、authoring.mq.md、delivery.mq.md | 用户版本确认、框架、作者模板、实际试运行与整合 |
| runtime/instructions.mq.md、prompts.mq.md、guides/ | 全部固定提示、阶段工程规范及上下文组装 |
| calls/*.mq.md | 当前角色真实可调用的函数、参数、返回及叙述 |
| proof.mq.md | 单元规格、独立案例冻结、摘要绑定与就绪判断 |
| runtime/child.mq.md、turn.mq.md | 单元内先测试后实现，有界重试、独立模型和真实交接 |
| runtime/knowledge.mq.md | 明确选择的知识材料与官方 knowledge preflight 复用检索 |
| ext/qdagent/native/src/runtime.rs | 官方 AST、受限文件与子进程、传输、事件、资源上限 |
| server/internal/app/native_entry.go、worker/provider.py | Go 直接执行根文稿及原样模型网络传输 |
| server/internal/app、frontend/src | 认证、存储、SSE、用户操作与官方 View |

独立规格只含当前单元的完整职责及公开契约，不附整个工程中其他单元的预期。规划者须把适用于该单元的约束写完整，并在 plan.mq.md 中交用户确认。已有验收不充分时返回规划，不能从实现补规则。固定正文以用户确认的原文作为公开契约，由独立角色调用确定性模板建立不同输入案例；原文中的真实引号和换行保持不变，预期不来自实现。其他业务由独立测试者明确填写输入与预期。案例、规则版本与摘要随同一份私有根状态原子保存，实现者没有更换案例的公开入口；原生边界也保留测试角色权限复核。

上下文每轮重新构造，只保留本角色上一次候选和必要诊断，总消息预算为六十四 KiB，超出明确失败。完整请求存放在私有运行目录；前端仅展示指令来源、摘要、体积和实际调用文稿。角色工作根为空，调用会话按运行、单元与角色区分。成功调用与阶段完成分别记录，只有失败才附带修复诊断；职责数量满足时，下一调用现场只提供发表函数。规划职责作为草稿跨轮原子保存，分别通过固定正文、输入取值和业务运算专用函数定义，最后发表实际框架。模型不能传入身份、文件根或阶段，也不能通过自造导入、宿主函数或控制流扩大权限。

所选知识身份随根状态保留，意图与规划读取限定材料，测试者不取得原文。reuse 使用官方知识编译器检索当前安装标准库，索引不是事实源，不自动授权候选。现有 Office 在交付阶段由普通函数显式接入，仍检查插件开关。旧交付缺少独立冻结案例时，最终验收明确拒绝并引导重新确认框架，历史文件继续保留。旧 catalog、executor 已退役并明确拒绝；历史技术栈迁移记录不再作为当前执行指令。

Return *"新增能力接入普通文稿，来源、权限、失败与验证一并维护。"*.

## verification

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 本次迁移的验证记录与实际限制 |

本次于 2026-11-14 已通过真实根协议八项、网络与完整文稿运行三项、知识与上下文边界两项、宿主架构防回退两项、Rust 六项及 Go race 检查。所有修改的根流程、阶段规范和调用文稿通过官方语法、契约与每函数叙述比例检查。测试网络替身的响应本身由可调用 Marqdo 文稿产生，仅替代模型生成，解析、状态、进程、文件、并发与案例执行均为真实路径。

故意错误返回会被另一角色冻结的案例拒绝，修复后使用同一案例通过。测试者尝试调用读取实现的函数在执行前被官方 AST 边界拒绝，并留下真实候选摘要和诊断。实际权限、旧确认失效、源码变化、部分验收、并行合并及知识路径越界均有负例，不能只依靠提示词约定。

八项真实浏览器用例通过，框架确认前还逐项核对返回原文，模型理解不符时通过实际返工入口补充并重新规划，未将错误草稿直接批准。用例覆盖首页、认证边界、工作台、模型与插件、上传、面板调宽、手机布局及官方只读 View。本机 Qwen 实际完成澄清、框架、并发细化、整合和最终用户确认；阶段规范接入后另行重跑该链路通过。这证明本轮明确任务可以运行，不证明小模型在任意复杂业务下都可靠。

当前根流程最多八个单元、并发一至八，框架规划最多十二轮，其他角色最多六轮。独立案例每单元一至六项，不能证明未覆盖输入。通用代码试运行只有受限文件效果，外部能力需要通过明确文稿与已启用插件接入；不能为了完成文字承诺自动放开宿主。所选知识超过十六 KiB 时明确提示缩小材料，未知文档格式仍需相应插件。模型预算用尽、语法持续错误或规格不充分都会保留未完成，不静默换模型或伪造交付。

Return *"验证记录说明已证明的行为；复杂任务仍须按同一真实证据链验收。"*.

## deployment

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 本轮容器与线上交付的验收边界 |

隔离容器使用只读根文件系统、非特权用户、进程和内存上限，数据使用临时目录，不对外发布端口。仅在这个测试容器内使用回环开发身份，生产认证继续启用。真实本机模型完成一个固定正文任务的澄清、框架、独立测试、实现、整合和用户验收，生成入口经实际 marqdo call 再次调用，返回值逐字为容器验收。开发身份的验收不等同于重新测试真实身份站账号登录。

生产继续使用原来的 7964 端口与 qdagent-data 数据卷，运行标识为 qdagent-document-runtime-0.6.0。切换前没有活动任务，SQLite 在线备份位于数据卷中的 pre-document-runtime-0.6.0.sqlite3。切换后任务、消息、个人模型和运行记录数量分别仍为十九、二十六、七、八，完整性检查通过。匿名模型 API 仍返回未认证状态，本机和远程健康接口及版本接口一致。

部署标识说明运行源码版本，不代表任意模型生成的业务内容都正确。后续更新应先运行文稿检查、关键协议与隔离用例，再构建镜像；部署前确认没有活动运行并保留数据库备份。模型出错时保留真实诊断，由用户审阅和相应阶段修复，不通过重启或修改预期制造完成状态。

Return *"保持原服务入口与用户数据，以真实文稿、测试、容器和线上版本共同验收。"*.
