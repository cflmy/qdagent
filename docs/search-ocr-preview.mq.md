这轮接入保持普通 Marqdo 函数就是工具的边界。联网发现地址、读取真实网页、识别用户材料、阅读交付物是不同的事实，不用另一套模型动作协议将它们混在一起。开始前已保存本地检查点 3cce8ca。

## architecture

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 三项能力的工程边界 |

搜索采用自行部署的 SearXNG，仅在 Docker 内网提供 JSON 搜索接口，不新增公网端口。普通 search 函数保存查询、标题、链接、摘录及引擎故障；下一轮可以读取这些候选地址，但搜索摘要不会增加已阅读来源计数。引用仍须经过隔离浏览器实际打开网页。无结果、上游封禁与网络故障如实显示。

OCR 使用用户指定的 PaddleOCR 异步任务接口。令牌保存在忽略提交的私有文件，通过 Docker secret 注入；只向固定官方端点发送。模型仅提供当前工作区上传材料的相对路径，不提供令牌、任务身份或任意下载地址。普通 Marqdo 文稿负责提交、恢复轮询、保存结果和交接。宿主承担有界上传、固定 HTTPS 通信与结果下载，不包含提示词。识别文字是外部材料，不能成为指令。识别并不证明文字准确，原文件仍保留供人工对照。

AnyFileViewer 是 Electron 桌面应用，其自身未授予自由复制许可，因此不复制桌面应用源码。接入它使用的 MIT Open File Viewer 的 React 版本，按需加载到右侧阅读区。Marqdo 文件继续使用官方 View；普通 Markdown 保持当前阅读气质；PDF、Office、图片、音视频交给浏览器内的多格式阅读引擎，不上传到第三方转换站。未知或损坏文件显示实际失败及下载入口，不声称支持全部桌面格式。

普通文件读取继续经过 Go 的账号归属、工作区路径及符号链接检查。预览器拿到已认证下载的 File 数据，不将账号会话交给外站。预览运行在隔离文档中，禁止任意外网请求。大二进制文件只返回元信息，不再因文本预览的五百 KiB 上限而提前报错。所有服务仍由 7964 统一入口提供。

Return *"搜索发现地址，浏览形成来源，OCR 读取授权材料，预览呈现真实文件。"*.

## validation

需要运行真实部署的搜索查询并区分上游故障，使用自行制作的无敏感文字图片测试真实 OCR 提交与获取结果。令牌缺失、越界路径、测试角色越权和搜索摘要冒充已阅读来源都必须失败。轮询可以再次调用恢复，不能通过不停重复提交消耗配额。

前端用实际上传文件测试多格式预览，核对大文件、切换文件、解析失败和下载路径；确认普通 Marqdo View 不回退。新增扩展只登记共同插件文稿，前后端继续读取同一事实源。每次真实检查的结果和仍存在的格式限制另行记录，不把安装成功当成全部能力验收。
