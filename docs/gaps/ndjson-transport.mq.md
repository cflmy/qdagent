标准库 subtask 的数字句柄属于当前宿主，不能直接当成不同 HTTP 请求之间的持久任务标识。
Ollama 原生流使用 NDJSON；既有 SSE 消费接口不能直接替代这一协议。旧实现把 Bash 文本当作后台
执行器，取消时又只杀 Shell，可能遗漏 curl 子进程，因此不作为正式实现继续使用。

本工程通过 ext/qdagent/transport.mq.md 加载 ABI v2 插件，注册 qdagent_transport。
原生源码只有任务动态库和专用 worker；传输模式按固定参数启动 curl，工作流模式只运行已安装入口的 marqdo call。它限定连接及任务总超时，
记录真实退出码，取消时检查进程身份，且用代数令牌阻止旧 worker 写回新作业的完成标记。

提示词与模型配置、工具注册与 Schema、效果账本连接、普通 Markdown 持久化与渲染、HTTP 端点和浏览器状态机
继续是 Marqdo 源码。每个会话拥有独立运行根和工作目录，可以切换与并行工作；这是任务隔离，不能宣传为多用户鉴权。

安装入口会在工程及站点根放置相同构建产物。主机需 Rust 编译器与 curl，插件只支持 Linux。
一旦 Marqdo 提供可跨请求定位、取消且支持 NDJSON 的原生作业能力，就替换此边界并删除插件。

启动、取消、PID 发布和完成标记共享同一工程的文件锁。旧 worker 即使恰好在新请求开始时
结束，也必须在锁内重新核对令牌，不能把旧退出结果写成新请求的完成标记。锁不覆盖模型等待期，
因此取消仍可进入；普通会话与提示词的业务事务并未因此获得多用户隔离。

跨进程控制锁是另一项真实 OS 缺口。每个会话的 begin、poll、stop 和 view 使用独立控制锁，避免两个标签页同时覆盖同一作业；模型等待在后台工作流，不占住控制锁。取消前检查受控进程的入口与根，停止整个 Marqdo 调用组，正常 TERM 等待后必要时升级 KILL。令牌检查阻止尚未发布 PID 的旧 worker 在取消之后重新启动。

工作流的提示、工具选择、参数校验和结果解释始终在 pages/agent/*.mq.md。插件不接受 Shell、Python 或 JavaScript 源文，不替模型伪造操作，不把渲染 Markdown 变成代码执行。新增操作必须先通过可信能力登记，再形成实际 marqdo call。
