## design

solution/plan.mq.md 保留用户确认的不可变骨架，solution/index.mq.md 从该骨架创建工作版本。两者的 ## unit_身份 一一对应。每个作者只填写一个函数段，不能增加函数、改其他段、改导入或接触测试规则。主文稿从细化开始就是可阅读的完整工程，不等最后拼接才出现。保存由官方 AST 定位函数区间，在锁内重读主文稿并只替换自己的区间；不能将某个作者的旧整文件快照覆盖其他人的成果。

独立测试依然只看确认规格的无执行语义投影。试运行取得主文稿中当前函数的隔离快照，不能读取同一文稿的其他实现。证据绑定导入和本段源码摘要；另一个作者更新其他段不会使本段验证失效，本段或导入变化则必须重新验证。运行依赖与开发顺序分别处理：普通函数按公开接口并行编写，不等另一个函数先实现。研究正文确实需要前置真实资料时仍等待资料，不能凭空补全事实。最后整合只补上按已确认依赖调用的 run 与工程叙述，不重新生成已经验证的函数。

旧任务可在下一次细化时将仍可读取的历史单元移入对应函数段。保留已确认规格与用户批准；不能替用户修改最初方案的依赖或验收。历史缓存摘要不一致时保留待验证状态，不能追认成功。前端明确显示主文稿、函数名和各段进度，而不是把职责描述当成另一项完整工程。

真实失败记录还显示：Wikipedia DNS 同时返回特殊用途 IPv6 地址，防护因此正确拒绝；NASA TLS 多次失败；空正文被误记为来源。此次保留网络防护，拒绝无正文或验证页面作为有效来源，保存失败地址及原因，同一地址连续失败后停止重复网络开销，引导选择其他搜索候选。公开网络不保证每个网站可访问，不能为完成任务绕过内网防护或编造资料。

新任务在首次有效输入时取得简洁名称，已由用户命名的任务不被覆盖；标题不依赖额外模型网络请求，不阻塞正文流。所有固定指令和修复建议继续保存在 Marqdo 文稿中，宿主只负责受限读写、解析、锁、认证与事件。
