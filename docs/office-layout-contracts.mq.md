title: 办公模板开发规范：布局即函数，写入前校验
---

本规范适用于全部新增 Word、PPT 与其他办公模板。模板不只是一组样式文件，它是一组有真实输入约束、渲染区域与验证证据的 Marqdo 函数。所有固定模型说明与业务约束继续只写在可执行文稿中。

## contract

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 每种布局都必须实现的工程要求 |

每种布局使用独立函数，按内容语义接收标题、左右列、引文与出处、图片与说明等明确参数，不接受任意 HTML/XML、坐标或样式脚本。标题下面先给参数和返回表，列出类型、必填、有效最小字数、原始最大长度、行数、单行长度及素材要求，再解释场景、例子与真实操作。每函数叙述超过一半，操作尽量嵌入有意图的正文，返回值自然承接说明。

上限与下限由实际字号、区域、行距、语言与用途共同决定。PPT 双栏分别核对，不能拿右栏字数弥补左栏空白；引文保留出处；图文保留替代说明或图题。Word 连贯报告允许自然跨页，提示块和短结论则使用不同预算。短内容选择重点句布局，不凑字；长内容按已确认逻辑精炼或拆分，不随意缩字、裁掉结论或破坏用户要求逐字保留的原文。

约束函数是唯一规则来源。构造、创建、编辑、自动组装与重建旧源稿共用同一函数，不另建一份 JSON 工具参数表或宿主正则规则。结构记录只是业务数据，模型仍通过普通 Marqdo 函数调用执行。预算、渲染与模板版本一同维护，不能只改模板尺寸而保留失效字数限制。

Return *"每种布局一个可读函数，预算与实际区域绑定，所有写入口复用同一契约。"*.

## preflight

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 写入前的完整检查顺序 |

先检查整份文件的题目、格式、内容块数，再重新构造每一块，核对版本、所有字段、派生正文与素材。只有全部通过，才分配版本身份、创建输出目录、保存源稿、嵌入素材、打包、重新解包并登记文件。第二页错误不能让第一页先产生一个被误认为完成的文件。错误保留布局名、字段、实际值和允许范围，便于模型修复。

素材从当前已授权任务取得，不让模型自报尺寸和摘要。当前实现仅支持已上传静态 PNG，真实解码上限四 MiB，像素至少 640×360、单边最多 4096、总量最多一千二百万像素，比例在 0.4～2.5 之间；全部嵌入副本合计最多六 MiB。坏图、缺图、动画、越界和不合比例在写入前拒绝。图片等比例居中，不用空框、拉伸或裁切掩盖不适配。

预检通过后仍可能遇到磁盘或排版错误，所以不能把预检等同于交付完成。复制素材前后重验摘要，避免校验的是一张图而写入另一张。实际 PDF 生成、内容审阅与用户验收保持独立；失败保留真实候选和诊断，已经存在的旧版本不覆盖。不得扩大效果或降低预算来假装修复。

Return *"整份请求与实际素材先通过，再写入；静态预算、真实渲染与业务验收分别证明。"*.

## evolution

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 模板开发与回归要求 |

新布局同时交付函数、固定模板、完整校验、源稿结构、编辑方法与实际渲染用例。测试包括最小值、最大值及越界值、空白、单行与总量、缺少字段、手工伪造记录、后续块失败不产生输出、坏图和图片比例、旧版保存、派生字段一致性。通过实际 ZIP/XML 不等于排版正确，还需在真实引擎生成 PDF，并查看文字和图片的可读呈现。

源稿保存布局身份、版本、字段和真实素材摘要。双栏、引文或图文编辑应重新调用布局函数构造完整记录，不能只改 body；生成器拒绝正文与字段分离。新增版本不能覆盖旧版，不支持的布局或版本应明确拒绝，不能悄悄回退到通用正文。旧普通输入也必须先被明确分配到实际布局并校验。

当前根流程从已验证的函数段组装正文，默认使用正文或重点句页，Word 按内容选择流式报告、提示或短结论。不能把默认正文交付宣传为已经自动选择所有专用布局。需要特定布局时使用实际手册中的完整函数与记录，规划和验收同样约束最终呈现；新增智能体入口也必须保持真实正文的来源联系。

Return *"模板、契约、源稿和验证一同演进；真实能力与默认流程的范围明确区分。"*.

## verification

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 本次实现的实际验收范围与边界 |

本轮以真实 Marqdo 调用验证十种布局，包括 PPT 六种与 Word 四种。构造、整份写入、旧版修订和根流程组装都走实际入口。字数上下限、空白、行数、单行长度、伪造派生字段、坏图、缺图、错误校验和、比例与目录逃逸用例均已执行；后续块失败时没有生成版本目录或交付登记。有效英文空格不会被误算为内容，比例使用整数交叉比较，避免整数除法误放宽边界。

固定回归执行三十四项协议测试，其中三十三项通过，一项原有外部浏览器环境测试跳过；另有十二项 Rust、九项传输与服务测试、Go 竞态检查通过。十六项真实浏览器用例通过，包括实际办公文件预览。测试程序只提供输入与观测，固定模型场景仍定义在 Marqdo 文稿中。

在隔离容器中用真实 LibreOffice 生成三份 PDF：普通 PPT 六页、达到布局上限附近的 PPT 六页、Word 两页。提取结果核对实际文字数量及页面边界，图片保持比例；人工查看双栏与 Word 图文，修正了图文正文与图片跨页分离。该检查覆盖当前固定字体与排版引擎，不宣称任意软件、字体或用户内容都能像素一致。

真实供应商模型调用也完成已确认正文、冻结独立测试、办公组装与 PDF 生成，进入审阅而非自动代替用户验收。当前默认根流程仍使用正文与重点句布局；其他专用布局通过各自函数显式构造。源稿、实际文件、预检和最终审阅各自承担不同证据，不能把本次测试记录当作未来任意内容的免检资格。

Return *"模板函数、写入前预检和实际排版均已验证，默认编排范围与人工验收边界保持明确。"*.
