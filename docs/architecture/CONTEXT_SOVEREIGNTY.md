# 求道：Marqdo 原生自主上下文架构

> 状态：**目标架构设计 / ADR 提案**，2026-11-19。此文档优先于此前“模型始终只能看三份文本”的实验性描述。**本轮仅更新设计，不实现、编译、测试或承诺当前代码已遵循这些契约。**

## 一、核心原则：上下文主权属于 Marqdo 智能体

智能体不是外部 Agent Loop 准备好一个大 prompt、再让 Marqdo 代为执行的系统。

1. **极小默认启动（Bootstrap）**：当前用户输入、持久记忆文稿、当前运行的 Marqdo 文稿。这三项是默认基底，不是最大集合，也不是每次必须全文加载。
2. **模型自主请求（Demand-driven）**：只有智能体发现缺少信息时，才主动选择来源、粒度、时间范围与预算；不允许框架事先替它灌输一个固定工具目录、整段历史、所有源码或大批搜索结果。
3. **Marqdo 负责上下文决策与装配**：选择、局部读取、投影、压缩、固定/释放、引用与再验证由可阅读、可测试的 `.mq.md` 函数表达；运行时仅提供来源解析、访问权限、空间配额、实际模型传输。
4. **上下文与权限完全正交**：模型可以提出读取请求，但请求不能产生访问授权；只有宿主/沙盒已经允许的资源可以进入上下文。
5. **来源可寻址、可验证、可失效**：引用应指向具体文稿/符号/锚点/版本，不是靠一段不带出处的模型摘要充当事实。
6. **最小必要而不是最少字数至上**：有时完整函数是必须阅读的；应当允许选择完整函数，但不能默认加载整个仓库。
7. **暂态工作上下文与长期记忆分开**：一段临时读入的资料不会因为模型看过就变成长期记忆；沉淀需独立验证和明确策略。

### 正确的基本模型

```text
            用户请求
                │
         Marqdo 智能体文稿
                │
          bootstrap（最小）
           ├── user.current
           ├── memory.relevant / memory.mq.md
           └── source.active
                │
           模型提出缺口？
           ┌────┴────┐
           否         是
           │          │
           │    context.request(...)
           │          │
           │    Marqdo 引用/作用域选择
           │          │
           │    安全读取、来源校验、预算
           │          │
           │    当前轮可见上下文视图
           │          │
           │    推理、继续读取或释放
           └────┬─────┘
                │
       Marqdo 函数/工作流继续执行
                │
        真实证据及必要记忆沉淀
```

**模型可以主动补充上下文，但没有权力自行扩大权限。** 任何上下文扩展都是一个可追踪的 Marqdo 执行步骤，而不是网络/模型传输层偷偷增加消息。

## 二、上下文分层：五种不同性质的东西

| 层 | 类型 | 决策者 | 特点 |
|---|---|---|---|
| A | **启动基底**：用户输入、记忆入口、活跃文稿 | Marqdo 当前任务 | 默认极小；记忆可按作用域读，不必全文 |
| B | **即时工作集**：函数、类、文档片段、锚点、查找结果 | 模型请求 + Marqdo 校验 | 动态加载、有生命周期、精准来源 |
| C | **执行观察**：工具收据、文件差分、错误、测试、实验输出 | 当前 Marqdo 工作流 | 只选当前决策真正需要的证据，不重放完整日志 |
| D | **持久知识**：已审核记忆、知识制品、证明/测试引用 | 记忆与知识规则 | 版本化、可追溯、可失效、可以未来再读取 |
| E | **可信运行环境**：用户身份、权限、租户、凭据、配额、执行隔离 | 宿主/沙盒 | **不属于模型上下文**；永不因为读入源码而授权 |

B/C/D 可以按需进入模型当前注意力视图，但 E 永远只是可信能力边界。上下文片段中的文本均按其来源可信等级处理，不能因为“模型自主选择”就获得系统指令权。

## 三、精细粒度的选择单位

上下文选择首先是**语义寻址**，其次才是字符区间或 token 数。

| 来源 | 建议的最小寻址粒度 | 扩展时机 |
|---|---|---|
| Marqdo 源码 | file → class(#) → function(##) → statement/anchor | 精确定位函数、依赖、调用点 |
| Markdown 知识 | 文档 → heading → 段落 → 锚点与反向引用 | 查找局部知识、定义和论证 |
| 编译知识图 | SymbolId、定义摘要、依赖闭包、claim | 需要确定某知识能否复用 |
| 证明证据 | proof-deps、obligation、模型证书、Lean replay receipt | 需要区分模型证明与执行保证 |
| 运行证据 | 单次调用、错误诊断、测试用例、输出差分 | 需要修复、验证或决定下一步 |
| 会话/记忆 | 决策摘要、已认可事实、开放问题、用户明确约束 | 需要跨轮连续性 |
| 外部资料 | 确切 URL/页/片段、检索时间、提取质量 | 需要可核对的公开来源 |

**优先使用现有 Marqdo `ext/ai/context.scope`、官方知识索引、稳定锚点和编译产物。** 新的 qdagent 上下文层应组合这些能力，而不是再写一个依赖字符串匹配的平行解析器。源头无法解析时返回明确错误，不能偷偷退化为整个文件。

## 四、建议的 Marqdo 接口（概念契约，非当前已实现函数）

建议在 `agent/context/` 中形成以下语义接口。下面是**拟议的 API 名称**，不能当作现有 CLI 或已可运行 Marqdo 语法：

```text
context.bootstrap()                    # 启动最小注意力视图
context.request(ref, scope, purpose)   # 模型明确表达缺少什么
context.search(query, domain, limit)   # 找到候选可寻址知识
context.inspect(ref, depth)            # 仅观察来源元数据、边界和目录
context.read(ref, span, max_tokens)    # 读取精确片段，返回引用与摘要
context.expand(ref, depth)             # 加载上级/被调函数/依赖
context.pin(ref, until)                # 在本工作阶段固定需要的片段
context.release(ref)                   # 释放不再必要的片段
context.compact(policy)                # 保留约束、来源、事实与未决问题
context.snapshot()                     # 查询当下究竟有哪些上下文
memory.propose(facts, references)      # 提议沉淀（不自动变成可信记忆）
memory.commit(approved_facts)          # 在独立证据/权限门禁后写入
```

不要求每个领域 SKILL 显式把 `context` 字典向下传递。一个工作中的 Marqdo 文稿通过 `context.read` 等函数访问**其自身的有界工作集**。这个工作集属于 Marqdo 任务，而不是 Go/Python 组装的消息数组。

一个读取结果至少包含以下结构：`ref`、`source_sha256`、`scope`、`excerpt`、`trust`、`token_cost`、`revision`、`expires_on`。模型得到的是片段内容和来源；宿主验证授权、尺寸和作用域。来源变化、权限收回或版本失效时，对应片段不应继续当作有效事实。

## 五、上下文请求怎样由模型发起？

模型可以在当前 Marqdo 文稿提供的协议下提出一个**结构化请求**，例如：

```text
CONTEXT_REQUEST
  ref: mq://marqdo/src/knowledge/unified#compile_project
  scope: function
  purpose: inspect caller/postcondition contract
  budget_tokens: 1800
```

这只是**模型建议的读取需求**，不是直接文件读取权限，也不是任意代码执行。Marqdo 校验具体引用、来源与预算，再调用 `context.read`；读取成功后该片段才进入下一轮局部上下文。模型可以继续请求 `dependency`、`caller` 或 `test-case`，也可以 `release`。

智能体不必每次都发请求：没有上下文缺口就直接执行当前函数；涉及纯确定性逻辑时甚至无需模型调用。这样才能发挥 Marqdo 编译控制流和知识引用的价值。

## 六、工作集策略：自主选择 + 确定性保护

默认策略建议：

- **On-demand**：未明确要求时，除了 bootstrap 不预载未知材料；
- **Scope-first**：先取锚点/函数，再在必要时扩至类/文档，绝不以仓库全文作为默认回退；
- **Budget-aware**：上下文窗口是有限资源；由 Marqdo 记录不同片段占用与剩余额度；
- **Pin / release**：冻结规格、显式用户约束、当前执行函数可以优先保留；过期浏览页面、无关日志、重复来源自动进入可释放候选；
- **Evidence-aware**：来源不可信、模型自己写的摘要、受限 Lean 证明、真实测试收据不可混为一类；
- **Stable-reference**：检查点优先保留 `ref + digest + scope + state`，只有下一步确实需要才重载文本；
- **No silent summarization**：压缩必须声明被保留的约束、来源、损失与摘要的可置信性；
- **Explicit denial**：没有权限、找不到来源或超预算时返回原因，而不是编造补充材料；
- **No accidental memory writes**：临时阅读与持久学习分开；工作记忆可能随步骤失效，长期记忆需要有证据的提交。

可以由不同 SKILL 选择不同的预算策略。例如研究 SKILL 需要精确引用原文，代码 SKILL 优先函数定义与诊断，量子科研 SKILL 优先电路、观测与实验来源。**没有全局唯一的“最佳切片大小”。**

## 七、多智能体与并发时的作用域

任务根下允许多个 Marqdo 子文稿同时执行，但**不能默认共享各自注意力上下文**。

- 每个子任务持有自己的工作集、预算和调用来源；只共享明确公开的只读知识制品引用；
- 跨任务传递 `ref + digest + conclusion + evidence`，不传子模型完整隐藏历史；
- 合并结果时由父文稿选择哪些证据进入自己的工作集；
- 并发写入、权限与副作用由执行环境强制仲裁；
- 可重放检查点记录上下文选择过程和来源版本，不依赖重放一份不可见大 Prompt。

## 八、具体开发目录

```text
agent/
  index.mq.md              # 根文稿：任务流程与能力路由
  model.mq.md              # 仅传输桥接；请求的工作集由 Marqdo 生成
  session.mq.md            # 身份隔离的会话事实
  memory.mq.md             # 记忆入口 / 提交规则
  context/                 # 新增：上下文架构核心（拟议）
    index.mq.md            # bootstrap / request / inspect / read / pin / release
    scope.mq.md            # 函数、锚点、段落、图依赖寻址
    workspace.mq.md        # 当前工作集、配额、快照、压缩
    provenance.mq.md       # 来源版本、信任与失效
  catalog.mq.md            # 已安装 SKILL 的事实索引
  decision.mq.md           # 最小自主选择
  executor.mq.md           # 明确执行已安装文稿
skills/<domain>/           # 每个 SKILL 自己决定何时扩展上下文
workflows/<domain>/        # 跨步骤状态与证据引用
ext/ai/ + ext/knowledge/   # 优先复用 Marqdo 现有源作用域与知识函数
ext/qdagent/native/        # 只提供 OS 权限/来源解析/模型传输原语
```

目录里的 `agent/context/` 为后续开发目标，**当前分支没有创建这些可执行实现**。是否进一步合并到上游 `ext/ai/context.mq.md`，要根据接口成熟度与复用性决定，避免两套语义分裂。

## 九、推荐实施先后次序（仅设计）

- **A1：模型调用协议**：把“固定只能三源”的运行时限制改为“bootstrap + 经 Marqdo 明确选择的有来源片段”，禁止外部宿主任意注入；
- **A2：精确作用域**：复用官方 parser、`ext/ai/context.scope` 与知识编译器，以稳定引用实现 `inspect/read/expand`；
- **A3：工作集生命周期**：`pin/release/snapshot/compact`，准确记录 token、来源与失效；
- **A4：SKILL 自主读取**：研究、代码、量子等领域拥有不同策略，根不再维护全局工具提示；
- **A5：长期学习**：临时阅读 → 明确证据 → 受控记忆写回，支持跨任务引用而不回放全部历史；
- **A6：证明与回放**：为重要上下文选择记录来源/闭包摘要，用真实证明与独立实验验证而不夸大保证。

验收重点应是：模型是否自己发出必要读取、是否避免多余上下文、单步 token 开销、精确引用与失效、不同领域技能迁移、权限封锁和上下文压缩后的任务成功率。**不是“越少上下文越好”，而是“每段上下文都有必要性和来源”。**
