# 如何新增一个真正可复用的 Marqdo SKILL

新范式不再复制根状态机，也不需要修改一张人工维护的工具 JSON 列表。

## 最小能力

复制 `docs/examples/minimal-skill.mq.md` 到 `skills/<slug>/index.mq.md`。slug 只含小写字母、数字和连字符，长度不超过 48。文稿头部写好 `description` 和 `agent_effects`。运行函数必须明确声明 `context`、`goal` 两个参数。

**规范**：

1. `run` 是该能力对根的唯一默认入口；内部可以自由拆成多份 .mq.md、多个 ## 函数，无须修改根；
2. 用自然语言写清职责、输入、结果、证据和失败；不要重复复制全局身份规则；
3. 能从 Marqdo `ext/` 或 `lib/` 组合得到的能力，不新增宿主语言业务实现；
4. 执行前核对效果授权。读取资料与外部写入属于不同权限；
5. 模型文本只是候选。若需要代码，先写文稿、由官方解析器检查，再独立测试和审阅；
6. `Result.ok` 只代表接口过程成功，真正完成条件应由该业务函数返回的状态与真实收据决定；
7. `model_proved` 不等于设备/插件层完整正确性；证明、测试和假设来源必须分开标注。

## 真实开发路线

- 设计一个小领域能力，给一份 `index.mq.md` 和至少一个不依赖外部模型的纯示例函数；
- 从 `agent/catalog.discover` 看安装投影，从 `agent/catalog.resolve` 看源码 SHA、效果与路径绑定；
- 经真实用户权限调用 `agent/index.run`，由 `agent/executor` 执行该 SKILL 的 `run`，不能将随机字符串拼成源码文件路径；
- 多阶段工作放在 `workflows/<domain>`，持久化由 Marqdo 原生 workflow 管理，主根不增加领域条件；
- 领域任务需要专有记忆时，建立引用到知识制品的短收据，不向根注入整个插件手册。

新增能力时优先保持两个事实：**SKILL 是普通的 Marqdo 源文稿**，**源码以及真实效果收据是所有运行的权威依据**。

这份指南说明目标契约，不代表当前分支已经完成任何端到端测试。
