# 求道 v3：架构决策与理由

状态：2026-11-19 探索性基线，**代码未通过编译、集成与生产验收**。此文档回答“为什么采用这种架构”，不是对实现成熟度的承诺。

## 核心选择：文稿是能力，执行由语言负责

求道不是“聊天模型 + 预置 Python 工具列表”，也不是要求 LLM 每轮生成整套执行计划的巨型状态机。**Marqdo 源文稿同时包含阅读说明、函数接口、可寻址知识和实际计算**。智能体只需要按需发现并调用该文稿的函数。由此获得源码可审阅、文档可复用、局部知识可证明与执行证据相互连接的路径。

```text
               用户请求
                  │
             Go 认证 / 任务
                  │
       agent/index.mq.md（一份根）
          ┌───────┼─────────┐
       session   catalog   decision
         状态    源码索引    短候选选择
          └───────┼─────────┘
              executor + effects
                  │
       skills/<slug>/index.mq.md
              │             │
          单步函数     workflows/<domain>
              │             │
          ext/ + lib/ + Marqdo 编译执行
                  │
         来源、测试、证明、真实收据
```

## 七项必须坚持的决策

| 决策 | 为什么 | 不采用的方案 |
|---|---|---|
| **一个极薄的 `agent/` 根** | 新领域不改变核心，不把某一业务流程变为所有任务必经路由 | 巨型 root skill、每个子能力再造根 |
| **一份 SKILL 一份实际入口文稿** | 源码、API 与可读解释同址，改动可 diff、可审阅、可引用 | 人工同步 JSON 工具清单、独立 Prompt 工厂 |
| **业务流程只存在于对应 `workflows/`** | 简单回答不需工程审批，复杂任务才付出规划/检查点成本 | 将意图→拆分→实现→测试强制套用到每轮 |
| **模型只选择 ID 与最小决策** | 小模型可在短上下文稳定运行；错误更容易定位 | 无限制生成 Shell、路径、代码来决定调度 |
| **状态与记忆分离** | 状态是受信事实、记忆是无权限的 Markdown 投影，避免指令注入成为授权 | 把完整历史、权限和模型自述堆成一个上下文 |
| **宿主只管信任与 OS 缺口** | 人类可读程序保留在 Marqdo 中，同时认证/进程/文件/超时仍可靠 | 一切写进 Rust/Go，或把身份验证交给 LLM |
| **证据有明确等级** | 可审阅文稿、语法/模型证明、运行测试的结论边界不同 | 让模型自称已证明或把成功退出码当作业务正确 |

## 三条高优先级非目标

- 不恢复 `ext/root-skill/`、`pages/` 或旧的四阶段代理；Git 历史是迁移参考，不是新代码的依赖。
- 不为了“足够智能”把所有扩展描述塞进模型消息，也不维护一张与实际 `skills/` 重复的注册表。目录自动发现与权限许可是不同事实。
- 不为了维持兼容性继续运行 V2 状态；新版本允许不兼容，旧任务迁移需显式独立设计。

## Marqdo 的特性怎样最大化

1. **Markdown 原生**：`index.mq.md` 可以先被人阅读，函数 `##` 才是可调用能力。文稿本身是最小知识资产。
2. **可寻址引用**：能力之间使用显式 import 和函数引用，知识可围绕稳定源码锚点与源摘要组织，而不是靠模型记忆“可能存在某个函数”。
3. **组合执行**：复杂工作由 `workflows/` 编排已有函数，避免重复发明 Agent Loop；并发与依赖交给真实执行控制。
4. **可验证**：来源、契约、官方编译检查、受限 Lean 证明和独立执行证据分别保存。Lean 只能覆盖已建模语义，插件、副作用与真实量子设备仍需假设/收据。
5. **可沉淀**：成功的领域知识可变成独立文稿、锚点与测试；不能只留成不可检验的长提示词。

## 维护者判断新代码该放哪里

- 可重用的纯函数/格式处理？`lib/` 或既有 `ext/<domain>/`；
- 完整且可被用户选择的业务能力？`skills/<slug>/index.mq.md`；
- 多步/恢复/并发？`workflows/<domain>/`，由 SKILL 引入；
- 源码证据、证明依赖、学科规则？领域 SKILL 与知识工作流中的可读文稿，而不是 `agent/`；
- 需要文件锁、可信身份、隔离浏览器、进程、网络传输缺口？先研究现有 `ext/`，确实不足再加 **狭窄** `ext/qdagent/native/` ABI；
- 只是给用户展示状态/批准效果？`frontend/` + Go API，不再建 `pages/`。

## 维护期的完成定义

一项新能力至少拥有：真实可读 `run` 文稿、精确 effects 分类、可信执行上下文、明确失败/未完成语义、必要的独立证据。**“已编写源码”“被目录发现”“模型返回成功”是三件不同的事**。实验分支当前仅完成架构与源码清理，产品可用性由后续测试确认。
