# 决策：让 Marqdo 而不是外部 Agent 框架管理模型认知

状态：实验分支，2026-11-19。尚未完成编译、真实模型、权限和 Web 验收。

## 为什么要去掉 context 参数？

V3 最初设计看起来像“Marqdo 原生”，但每个函数都收到 `context`，还有通用 `model.ask(prompt,role,sources)`。这种实现事实上在 Marqdo 之外维持第二种上下文定义：调用层可以为每个模型步骤拼系统规则、摘要、工具列表和更多源码，文稿本身不再是模型理解的主要依据。

**现在的契约是：用户输入 + 记忆文档 + 当前执行的 Marqdo 文稿。只这三项。**

```text
Go 宿主认证一个真实任务（隐藏身份、许可、额度）
                  │
                  ▼
       marqdo call agent/index.mq.md run
                  │
          Marqdo session / catalog
                  │
         Marqdo decision.choose
                  │
                  ▼
         agent/model.ask()
           ├── ① 本轮用户输入（会话真相）
           ├── ② workspace/memory.mq.md
           └── ③ agent/index.mq.md 源码
                  │
        精确 SKILL ID 校验 / 效果授权
                  │
          Marqdo SKILL.run()
                  │
    专业 SKILL 再请求模型时，同样只看
       ①本轮输入 + ②记忆 + ③该 SKILL 源文稿
```

## 为什么仍有宿主与 Rust？

“模型没有 context”并不意味着“权限不需要上下文”。会话身份、账户、凭证、进程、路径、效果授权仍需要受信的系统事实。它们在进程内隐式获取、精确核验、记录收据，**不会作为消息文本进入模型**。这是一条操作系统的信任边界，不是第二个 Agent 框架。

原生 `agent_model_turn` 不接受任意消息、Prompt、来源或历史；它从会话、workspace 和记载的活跃 Marqdo 源文件装配三条原始消息，再交给传输层，其他协议字段只用于计量和认证。通用 `runtime_model` 的任意消息入口在新运行路径上已禁用。模型输出只当作数据，由 Marqdo 流程决定下一步。

## 动态能力发现会不会变成第四份上下文？

不会。SKILL 定义是自己的 `.mq.md` 文稿。运行时 `catalog` 用官方 parser 枚举 ID，决策文稿不再临时把目录列表拼成 Prompt。

有一个必要约束：如果模型要选择动态发现的能力，就必须能从**当前执行的文稿**读到可用的能力名称。因此 `scripts/sync_capabilities.py` 把真实 SKILL `description` 自动编译为 `agent/index.mq.md` 的 Markdown 表格章节。这个表是当前文稿内容，模型只收到当前文稿本身；运行时仍用实时解析列表对输出进行再次核验。新增技能后需重建该表；生成内容过期时验证流程拒绝继续。

这项取舍是为了同时保留 **“仅三源”** 和 **“可扩展的自动能力发现”**，而不是人为维护第二套注册表。

## 为什么不是直接使用 ext/ai/agent.step？

上游 `ext/ai/agent.mq.md` 提供非常丰富的通用代理循环、工具描述、来源拓展和 READ/CALL 协议；直接调用它默认的 `build_step_context` 会超出用户限定的三项。因此本项目复用 Marqdo 的语言执行、`ext/ai/workflow`、工具插件和来源处理能力，但**不调用那套默认的多段 Prompt Agent Loop**。

这不是拒绝上游 Marqdo：恰恰是让“当前正在执行的文稿”成为真正的行为主体。上游 `ext/ai/flow` 和 `llm` 可以继续作为受限能力使用，但任何调用路径不能破坏三源不变量。

## 知识与记忆的作用域

唯一默认模型记忆文件是工作区 `memory.mq.md`。它目前由会话状态投影生成，而不是完整聊天回放；这个版本尚未提供高级知识筛选/长期记忆自动学习算法。知识库和证明仍作为外部持久制品按需执行、校验、引用，**不能再往模型临时塞第四份材料**。需要模型处理新知识时，应把它作为当前被执行的领域文稿结构与数据处理结果，且不能冒充正式证明。

## 不变的安全边界

执行来源必须是受信安装位置；不能执行模型生成的文件路径。外部与写入效果须经原生审批及源码摘要核对。证明等级由真实来源/模型作用域/运行测试共同确定，`model_proved` 不意味着运行时万能正确。

**三源是模型输入协议，不是取消系统身份、安全、执行、审计和证据。**
