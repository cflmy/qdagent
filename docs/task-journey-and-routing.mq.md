本规范补充文稿驱动架构与函数段并行规范。界面展示真实执行记录，Marqdo 文稿仍定义根流程、意图拆分、受限路由与用户确认。本文中的可调用规则供后续开发直接阅读与核对，不新增业务工具登记表。

## journey

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 阶段回看与返工的区别 |

四阶段导航在任务完成后继续可用。用户可以回看意图问题、实际回答、基本方案、逐段实现与交付验收，不需要重新发送消息。切换回看只改变浏览器的阅读状态，不调用模型、不重新执行、不提交批准，也不清空当前正在填写的回答。当前阶段的人工操作与只读历史分开呈现，回到当前步骤后才能继续实际流程。

根状态的阶段迁移或待确认卡片关闭时，journey.archive 保存真实阶段、版本、职责、SKILL、用户交流及证据摘要。基本方案与交付入口在摘要一致时另存源码副本，官方 View 阅读该副本。未保存旧源码的历史只能说明仍保留哪些事实，不得将当前源码称作过去的精确快照。历史记录不给独立测试者附加上下文，也不扩大任何模型角色的文件权限。

返工必须由认证用户在当前版本上明确提出。调整基本方案仍受原意图约束；需要改变意图或工作方式时使用重新对齐意图，清空旧批准后再提问。以前的文稿和决定作为历史保留，不随新的方案被覆盖。新目标保留以前的阶段记录，但不能继承旧目标的批准。现有任务缺少完整历史时据实展示已有交流和证据，升级不会追认从未发生的确认。

Return *"阶段可回看，决定可追溯；只读历史不改变当前执行权限。"*.

## workspace

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 文件树、可读名称与存储身份的约定 |

工作区以文件夹和文件组成树，目录可以展开与收起，选中文稿后树继续保留，方便在材料与成果之间切换。文件按真实相对路径识别，预览、下载、鉴权和 React 键都使用原存储身份，不能为了美观重命名底层文件或让同名文件互相覆盖。目录里的私有文件、符号链接和其他用户资料仍依原有边界拒绝访问。

服务器上传时添加的十二位随机前缀仅用于保存。文件树、预览标题、附件显示、阅读器内部 File 名称与下载文件名使用原可读名称。只识别 uploads 下的服务器前缀，不删除工程中用户主动命名的类似字符；原文件名本身含有十六进制前缀时也只去掉服务器增加的那一层。同名上传分别标示为同名文件并保留大小，点击时使用各自完整路径。

自动生成的正文和验收意图使用根状态已经记录的职责标题作为展示和下载名称，不让 u0 等内部函数身份变成用户必须识别的文件名。显示标题保留实际文件扩展名，工程入口 index.mq.md 和 plan.mq.md 保持规范名称；所有实际路径仍原样用于访问与校验。

对话发送给智能体的材料仍保留准确工作区路径，界面仅将明确的附件列表投影为可读名称，不能改动存储消息或把用户正文当成路径解析。文件树不在提示里暴露全部目录；子智能体仍然只取得当前职责明确需要的材料。二进制文件继续使用隔离预览，Marqdo 文稿继续使用官方只读 View，不另写一份语言渲染器。

Return *"存储身份准确唯一，展示名称清晰可读；文件树与预览共用原权限边界。"*.

## routing

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 根任务从复合意图到实际 SKILL 的可执行路径 |

主任务先使用 calls/intent.mq.md 的 task 函数逐项保存用户意图，随后使用 ask 向用户核对清单和真正未决的问题。任务名称、职责与工作方式在确认前可见；相同身份修订同一项，最多八项。研究、写作、固定正文、输入取值与业务运算对应已有模式，不因拆任务而制造工程管理占位函数。人工确认记录绑定这一版待办，模型没有代替用户确认的接口。

routing.resolve 是实际 Marqdo 函数。它根据明确的工作方式返回已接入文稿的真实位置、函数和可读名称。实际实现角色也通过同一个函数取得受限手册，不根据模型输出的任意路径加载插件，不把任务名解释为另一套 JSON 动作。搜索、浏览、OCR、办公等调用仍在所属普通文稿检查插件开关与权限。路由成功表示选定开发方法，不表示外部调用已经成功。

基本方案的下一段由 runtime/planning.mq.md 从未覆盖意图中分配，受限的 calls/outline-slot.mq.md 只让模型填写 title、purpose 或精确 content。身份、关联与工作方式由根程序注入，模型不必重复生成它们；全部覆盖且数量满足后才提供发表文稿。没有清单的旧任务保留原入口，可供显式修订。

基本方案每个二级标题函数用 intent_id 关联已确认意图，一个意图可以由多个同方式函数段完成。发表前检查所有已确认待办均被覆盖，拒绝遗漏、未知关联或私自更换 SKILL。真实源码呈现这一关联，用户批准其摘要后才允许子智能体并行填写各自的函数段。运行数据依赖与开发并发继续遵守函数段并行规范。

待办进度从对应函数段、实际试运行和最终用户验收投影。待确认、待规划、待实施、验证失败、已验证与已验收不能混为一个完成状态。模型不能写入任意完成百分比；独立测试者只取得自己的冻结规格，不读取根清单、实现、用户开发对话或其他子任务过程。增加一种 SKILL 应先实现真实文稿与验证，再组合根路由，不恢复供应商工具 Schema 或 Python 提示分派。

Return *"根任务拆意图并路由；函数段承接范围；真实验证推进待办；用户决定验收。"*.
